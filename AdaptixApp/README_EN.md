# AdaptixApp — Android Operator Console

[中文](README.md)

The AdaptixC2 team-server client for Android. It talks to **exactly the same server API as the web console**: same address, same operator account. If the web console can reach your server, the app can too — just enter the same details.

## Connecting (identical to the web console)

Prerequisite: a running AdaptixServer (the one you already open in a browser). For server deployment see the [repo root README](../README.md).

| | Web console (browser) | AdaptixApp |
|---|---|---|
| Address | `https://<ip>:<port>/<entry-path>/` (entry path = `Web.path` in `profile.yaml`) | **Enter only `https://<ip>:<port>` — no entry path** |
| Account | Operator username / password | The same credentials |
| Certificate | Browser shows a self-signed warning you must click through | Self-signed certificates work out of the box |

- Both `http://` and `https://` are accepted; without a scheme the URL is treated as `https://`.
- Connection flow (done automatically by the app, listed here for troubleshooting):
  `POST /api/login` for a Bearer token → `POST /api/otp/generate` for a one-time ticket → `WS wss://<ip>:<port>/api/connect?otp=…` for the realtime channel.

## Features

- **Connection profiles**: save multiple server configs locally; tap a saved profile to refill it in one go.
- **Dashboard** with five tabs: Agents / Listeners / Targets / Team Chat / Console.
  - Agents: online agent list and status.
  - Listeners: listener list.
  - Targets: target list.
  - Team Chat: interoperates with the web console team chat.
  - Console: pick an agent, send commands, review task history and output.
- **Realtime**: WebSocket subscriptions for targets / agents / tasks / chat events, with automatic reconnection.
- **Notifications**: alerts for new messages/tasks (Android 13+ asks for the notification permission on first use).

## Getting & installing

CI (push to main / tags) builds the APKs automatically and uploads them to the GitHub Release:

| Asset | Notes |
|---|---|
| `AdaptixApp-debug.apk` | Install directly |
| `AdaptixApp-release-unsigned.apk` | **Unsigned — will not install.** Sign it with your own key first: |

```bash
# Generate a keystore if you don't have one
keytool -genkey -v -keystore myrelease.key -alias adaptix -keyalg RSA -keysize 2048 -validity 10000

# Align + sign (zipalign / apksigner ship with the Android SDK build-tools)
zipalign -f -p 4 AdaptixApp-release-unsigned.apk aligned.apk
apksigner sign --ks myrelease.key --out AdaptixApp-release.apk aligned.apk
```

Requires Android 7.0+ (minSdk 24).

## Building locally

- **Android Studio**: open the `AdaptixApp/` directory, pick a device, Run.
- **Command line**:

```bash
cd AdaptixApp
./gradlew assembleDebug        # output: app/build/outputs/apk/debug/
./gradlew assembleRelease      # output: app/build/outputs/apk/release/ (unsigned)
```

Requirements: a JDK (the daemon toolchain is pinned to 25; Gradle downloads it via foojay if absent) and the Android SDK (compileSdk 37; missing components are auto-installed by AGP). Gradle 9.6 comes with the wrapper; `local.properties` is generated by the IDE and never committed.

## Security notes

- **The client trusts all TLS certificates** (friendly to self-signed servers). This enables man-in-the-middle attacks on untrusted networks — use it on networks you control, and prefer `https://` over `http://`.
- **Connection profiles (including the password) are stored in plaintext** on the device (SharedPreferences). Don't root or lend out the phone; uninstall the app before retiring the device.
- All traffic between the app and the server (login, commands, task output, chat) flows over that single channel — no extra server-side configuration or ports are needed for the app.
